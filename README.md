# 路演工坊 · Roadshow Studio

用对话生成、逐页精修 HTML 路演材料，并导出 HTML / PDF / PPTX。

- **模板**：输入风格、用途、受众、配色等，AI 生成一套可复用的版式库。模板只是模板：页面上的标题、名称、数字、日期和图表数据全部是占位符（「公司名称」「XX%」「类别 A」…），并包含通用组件：封面、目录、章节页、图文页、KPI 卡片、柱状/折线/饼图（内联 SVG）、表格、流程图与时间线、对比/矩阵、团队、结束页（页数少时在一页中组合）。上传的参考 PPT/PDF 只用于模仿视觉风格：生成模板时不把参考资料的文字交给模型，交付检查还会比对参考资料，照搬的公司名、句子、数据（8 个以上连续汉字、4 个单词以上的英文短语、具体数字）以及缺少图表/表格/流程或时间线都会退回模型修改。
- **路演材料**：先选模板，再描述内容并上传支持材料（图片可直接嵌入页面；PDF / TXT / MD / CSV / JSON 会被提取文字作为依据），AI 沿用模板样式生成完整材料。
- **参考图片 / 参考 PPT / 参考 HTML**：新建对话框和编辑器底部对话框（📎）都可以上传图片或 PPT/PPTX/ODP/Key/PDF/HTML。图片可选择“嵌入页面”（AI 可用 `<img>` 放进页面，如 Logo、产品图）或“仅参考”（只让 AI 借鉴风格/版式/内容）；PPT/PDF 会逐页导出为图片交给多模态模型，HTML 在断网的无头浏览器中按 `section.slide` / `.slide` 等页面元素逐页截图（没有页面元素时按 1280×720 分屏截取），并同时提取文字。新建模板时参考用于模仿视觉风格，新建材料时用于提取内容与结构（视觉以所选模板为准），修改时随本次修改附带。
- **只读文件工具**：参考文件往往远超上下文，短文档（≤6000 字）直接放进提示词，长文档只放开头预览和文件编号（F1、F2…），模型通过函数调用按需查阅：`list_files`、`read_text`（按页或分段）、`read_raw`（HTML/Markdown 等源码）、`search_files`、`view_page`（重新查看某页图片）、`list_archive` / `read_archive_entry`（直接读取 PPTX/DOCX 内部的 XML 与图片）。这些工具全部只读，只能访问本项目中本次提供的文件。
- **自检（智能体循环）**：模型输出初稿后，服务端在无头 Chrome 中渲染草稿并做 DOM 布局检查（文字超出页面、内容被容器裁切、文字重叠、图片加载失败、字号过小、空白页），把全部页面的缩略图总览和检查报告交给模型；模型可用 `render_pages`（渲染指定页并返回截图）、`check_layout`、`read_draft`（读取页面/CSS 源码）、`replace_in_draft`（精确替换片段）、`rewrite_page`（重写或拆分页面）、`delete_page` 查看并修复自己的草稿，修复完成才保存为新版本。工具只修改内存中的草稿，参考文件仍然只读；单页/元素修改时只有被修改的页面可写。若仍有错误会自动复查一次。可在「模型接入 → 生成设置」关闭或调整最多工具轮数（默认 10）；每次任务的自检结果（修复前后的错误数、修改次数）记录在任务中并在完成提示里显示。
- **多文件项目与生成说明（README）**：项目由 `README.md`（用户需求、风格约定、页面规划，以及系统自动追加的修改记录）、`styles/*.css`（如 `theme.css` 设计变量、`components.css` 组件样式）和 `pages/*.html`（每页一个文件）组成。默认**分阶段生成**：先由模型编写 README 与样式文件，再按页面规划每次生成 3 页（可调），单次输出不会过长；某批被截断时保留已完成的页面并缩小批次继续。之后的每次修改都会把 README 作为“生成说明”交给模型，模型在需求或风格变化时同步更新 README。编辑器「文件」页签可查看全部文件、定位页面、直接编辑 README（保存为新版本）；「导出 → 下载源文件」得到包含 README、样式和分页 HTML 的 ZIP。可在「模型接入 → 生成设置」切回旧的一次性生成。
- **交付检查**：每次生成/修改结束前（不受「自检」开关影响），服务端按导出结构把草稿组装为 `README.md`、引用全部 `styles/*.css` 的 `index.html` 和可单独打开的 `pages/*.html`，在无头浏览器中逐个加载，检查引用的文件/图片是否存在、脚本错误、页数与页面尺寸、浏览器能否解析各样式文件；并静态检查 CSS 语法、样式文件之间的 `@import`、未定义的 CSS 变量、页面中的 JavaScript（`<script>`、`onclick`、`javascript:` 链接会在保存时被移除），以及 README 是否包含「需求」「风格约定」「页面规划」且页面规划与实际页面文件一致。有错误时把报告交回模型用工具修复，最多 3 轮，模型也可随时调用 `check_project` 自查；**修复 3 轮后仍有错误，任务以失败结束**，错误信息列出仍未解决的问题（失败记录在修改历史中，可重试）。例外：保存时会被自动移除的 JavaScript 不会单独导致失败；修改任务中项目原本就有的错误也不算（只看这次修改带来的问题）；检查器本身出错（如浏览器无法启动）时保留草稿。单页修改只报告可修改文件的问题，README 问题只作提醒。结果显示在完成提示中（如“交付检查通过”）。
- **分步生成的容错**：规划阶段（README 与样式文件）缺少文件时把要求交回模型补全，最多 3 次；仍没有页面规划才失败，缺少样式文件则继续生成页面，由交付检查要求模型用 `write_file` 写出。样式写在 ```` ```css ```` 代码块里、`<file>` 路径没加引号、或样式文件被输出长度截断（保留到最后一条完整规则）都能识别。某一页连续 3 次没有写出时先跳过、继续写其他页面，交付检查会把未写出的页面交回模型补写；一页都没有写出才失败。模型返回空内容视为一次未完成，同样重试。
- **向用户提问**：需求含糊时，模型可调用 `ask_user` 提问（生成时在规划阶段，修改时在修改过程中；每个任务最多 3 次）。任务暂停，编辑器中出现问题卡片（选项按钮、自由回答、跳过），项目列表显示“待回答”；任何协作者都可以回答。跳过或超时（默认 30 分钟）后模型按自己的判断继续。问答记录保存在任务中。可在「模型接入 → 生成设置」关闭或调整等待时间。
- **先局部、再同类**：选中元素（或单页）修改时，模型先修改选中内容，再用 `find_elements` / `find_css` 查找其他页面上的同类内容（例如同一个项目名称、同一 Logo 的颜色），找到后调用 `extend_scope`：系统询问“全部修改 / 只改选中的”，同意后才开放这些页面和共享样式文件（其他页面只能改内容，不能拆分或删除）。修改要求里已经写明“全部 / 所有 / 统一 / 每页”等时直接开放，不再询问。修改记录会写明“并同步修改第 N 页和共享样式”。
- **上下文压缩**：按「上下文窗口 tokens」（默认 200000）估算每次请求的大小，自动收缩输出上限；工具循环中历史过长时依次丢弃旧截图、把已执行的旧工具结果替换为摘要、把最早的轮次折叠为一条压缩说明，接口返回“上下文超长”时自动减半输出重试。
- **逐页预览与精准修改**：所有材料以页为单位（默认 16:9，1920×1080，可选 4:3 / A4 / 9:16 / 1:1 / 自定义）。
  - 底部对话框直接输入 → 修改整份材料；可切换为“仅当前页”。
  - 在预览中**单击**元素（Shift/⌘ 多选）或**拖动框选**多个元素 → 只修改这些元素。提示词中会写明“第 N 页的哪些元素”（data-eid、标签、class、文字、当前 HTML），并附带一张用红框标出选中元素的页面截图（多模态）。
  - **双击直接改字**：只包含文字（和换行）的元素——标题、段落、列表项、按钮文字等——双击即可在页面上直接修改，不经过 AI（选中后点「✎ 直接改字」也可以）。Enter 保存，Shift+Enter 换行，Esc 取消，点击别处也会保存；输入内容按纯文字保存（不会被当作 HTML）。每次保存都是一个新版本，修改历史中显示“直接改字”和改前/改后的文字（点击可定位），也会写进 README 的修改记录，之后的 AI 修改能看到。**任意文字都可以直接改**：段落中夹着加粗数字、斜体、图标或换行的小字时，双击其中某一段文字，只有这段文字（两个子元素之间的文字）变为可编辑（绿色框），旁边的加粗/图标等保持原样；只有一段文字的区块也可以用「✎ 直接改字」按钮。**SVG 图表里的文字**（柱状图数值、坐标轴、环形图中心等 `<text>`/`<tspan>`）同样可以双击修改：在文字上方出现同字体的编辑框，保存后只替换这段文字（SVG 文字不能换行，换行会变成空格）。图示中文字被透明的图层（如页脚、装饰层）盖住时，双击仍会找到下面的文字；生成的图表中两段文字重叠时，修改画在上层的那段。双击图片、图标或空白处会提示没有可直接修改的文字。旧版客户端与接口不受影响：不带段落编号的请求仍只修改纯文字元素，历史记录格式不变（只是多一个可选的段落编号）。若保存前这段文字已被别人改过，不会覆盖对方的修改，并提示对方改成了什么。
- **多人协作与修改历史**：项目不设权限，所有用户可读写。每次修改生成一个版本，记录修改人、范围（整份/单页/元素）、提示词，以及**具体修改/新增/移除了哪些元素**（可点击定位）；支持预览和恢复任意历史版本。每条 AI 修改还显示耗时、模型调用次数、输入/输出 tokens 与平均输出速度；修改进行中，进度条实时显示当前输出速度（tok/s）和累计 tokens。**失败的请求同样记入修改历史**（发起人、范围、提示词、错误原因、耗时），任何用户都可以一键重试（以重试者的身份重新运行同一请求，每条失败记录只能重试一次）。同一项目的并发修改按项目串行应用，不同页面的修改互不覆盖。项目列表中，正在被修改的项目标题前显示加载图标。
- **从中断处继续**：生成或修改进行中，服务端随时保存进度（分步生成的规划与已写好的页面、一次性输出被截断后已输出的部分、工具修改的每一轮对话与草稿、完成的草稿以及自检与交付检查进行到第几轮）。模型中途掉线（如本地部署的模型重启几分钟）导致任务失败时，修改历史中这条失败记录显示「已保存进度：已完成规划与 6/12 页」之类的说明和「从中断处继续」按钮（首次生成失败的页面上也有），任何用户都可以点击，任务从保存处接着做，不再重做已完成的部分；仍是同一条任务、发起人不变，成功后修改历史中只留下这一个版本（标注「中断后继续 N 次」），耗时不计入失败后等待的时间。为节省空间，**只有项目中最近一次的修改在失败后保留进度**：之后有人发起新的生成/修改或保存了新版本（包括直接改字、恢复版本），旧的进度即被丢弃，只能「从头重试」；任务成功后进度也随即删除，不保留对话记录。服务重启打断的任务同样可以继续。
- **放映**：编辑器顶部的「▶ 放映」从当前页开始全屏放映（正在预览历史版本时放映该版本）。单击或 → / 空格 / PageDown 下一页，单击左侧边缘或 ← / PageUp 上一页，Home / End 跳到首页 / 末页；Esc、右上角 ✕ 或翻过最后一页即退出，编辑器停在放映结束时的那一页。所有页面预先渲染、淡入切换，翻页不闪白；页码与退出按钮在移动鼠标时出现，静止片刻后连同鼠标指针一起隐藏。放映时编辑器自身的快捷键不会生效。
- **分享链接**：编辑器顶部的「分享」生成一个链接（`/s/…`），任何拿到链接的人**无需登录**即可查看这份路演材料或模板的最新内容：左侧页面缩略图、翻页（按钮或方向键）、全屏「放映」（单击或方向键翻页，Esc 退出），手机上也能看；看不到 README、修改历史、素材等其他内容。已登录的用户打开链接时右上角是「编辑」，直接进入编辑器；未登录的访客点「登录后编辑」，登录后直接进入编辑器。分享对话框中可复制链接、「重置链接」（旧链接立即失效）或「关闭分享」；列表中已分享的项目标有「已分享」。
- **浏览器通知**：自己发起的生成或修改结束（完成或失败）、AI 提问等你回答时，浏览器弹出系统通知，点击打开对应项目；正在查看该项目编辑器时只显示页面内的提示，不重复通知。首次进入时页面顶部询问是否开启（浏览器只允许在点击后申请通知权限），之后可在右上角头像菜单「任务完成通知」中开关，设置保存在当前浏览器。需要网页保持打开（后台标签页也可以；后台超过 5 分钟后浏览器会节流定时器，通知可能延迟约 1 分钟）。浏览器只允许 HTTPS 或 localhost 网页发送通知：通过 `http://服务器IP:9090` 访问时开关不可用，请为站点配置 HTTPS 反向代理；内网临时使用可在 Chrome 的 `chrome://flags/#unsafely-treat-insecure-origin-as-secure` 中加入站点地址。
- **用户管理**：首次启动自动创建 `admin`（默认密码 `admin123`，可用环境变量修改）。只有管理员能创建/删除用户、重置密码。另有一个内置的 `mcp` 服务账户，供 MCP 客户端使用：不能用密码登录、不能删除，管理员在它的一行打开「允许 MCP 请求」，在「MCP 接入」卡片中生成 / 重新生成 / 撤销令牌。
- **MCP 接入**：AI 助手（Cursor、Claude Code、Claude Desktop 或自己的脚本）通过 MCP 创建路演材料：列出可用模板，再提交与网页「新建路演材料」相同的输入（名称、需要添加的内容、用途、受众、页数、画幅、其他要求、支持材料与参考），由服务端生成。工具说明要求调用方提交完整的测试数据与结果（环境、方法、每个指标的具体数值与对比表格、异常、结论）以及图表/截图图片和原始数据文件。详见下文「MCP 接入」。
- **模型接入（仅管理员）**：配置多个兼容 OpenAI Chat Completions 协议的接入点（Base URL、模型名、Token、附加请求参数），一键**联通测试**（含多模态校验：发送纯色图片让模型识别颜色）。接入点按**优先级**排列：在列表中拖动左侧手柄调整顺序（也可聚焦手柄后按 ↑ ↓），新添加的接入点排在最后。所有用户使用同一套**按请求**的调度：每个请求（包括同一任务中的每次模型调用）发往排在最前、未达到「并发上限」的已启用接入点，它满载时改发下一个，因此不同请求——包括同一用户的——可以并行分布到多个接入点；接入点故障时按优先级切换到下一个。每个接入点可设「并发上限」（0 = 不限；排在前面的接入点不设上限时，后面的接入点只在它出错时才会用到）：全部满载时新请求在本地排队，排队时间不计入「无响应超时」，适合一次只能处理少量请求的自部署模型（避免请求在模型侧排队而触发 “no response within 600s”）。**「并发测试」**依次同时发送 1、2 … 5 个相同的请求（让模型数数），测出接入点实际能同时处理几个：某一轮有请求失败（如 HTTP 429），或有请求要等其他请求完成才开始输出（服务端排队，复测一次确认）时停止，显示每轮的成功数、同时输出数、耗时与最慢首 token，并可一键把「并发上限」设为测出的值；输出很快的模型会自动数得更多（最多到 600），以免把偶尔偏慢的首 token 当成排队。测试请求不受并发上限限制，也不计入用量。每个接入点可选择是否**「使用系统代理」**（默认使用，即服务器的 `HTTPS_PROXY` / `HTTP_PROXY`，遵守 `NO_PROXY`）：模型部署在本机或内网、代理访问不到时关闭，这个接入点就直接连接，无需修改 `NO_PROXY` 重新部署；编辑框显示当前代理，接入地址是本机或内网地址时会提醒，列表中直连的接入点带「直连」标记，经代理连接失败时错误信息也会提示这一选项。「用量统计」单独成卡片，按接入点显示调用次数、失败次数、输入/输出 tokens、**平均输出速度（tok/s）**、平均首 token 延迟、平均排队时间与当前并发，并按用户 × 接入点汇总任务数、tokens、速度与费用。
- **会话（仅管理员）**：列出所有用户进行中与历史的生成/修改任务：项目、用户、请求、当前阶段（排队、等待回答、等待模型响应）、使用的接入点、耗时、调用次数、输入/输出 tokens、实时与平均输出速度；进行中每 2 秒刷新，点击一行查看每次模型调用的阶段、接入点、排队、首 token、用时、tokens 与速度。输出速度 = 输出 tokens ÷（最后一个 token − 第一个 token 的时间），不含排队与读取输入的时间；接入点未返回用量时按文本估算并标注。
- **一键部署与在线更新（Linux，默认端口 9090）**：`deploy.sh` 一条命令完成安装（Node.js、依赖、构建、系统服务、开机自启）；管理员可在「系统更新」页面一键检查更新、立即更新，更新前自动备份数据库，新版本健康检查失败时自动回滚并恢复数据。
- **导出**：HTML（自包含，素材内联，按 F 进入演示模式）、PDF（矢量，可选中文字）、PDF（逐页截图，与预览像素一致）、PPTX（每页一张 16:9 全幅图片，备注中附该页文字）。

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 后端 | Node.js 22 + TypeScript + Fastify | 路由按模块拆分（`server/src/routes/*`） |
| 存储 | SQLite（better-sqlite3，WAL） | 带版本化迁移（`server/src/db.ts`），素材文件存 `data/assets` |
| 文档模型 | cheerio | `server/src/deck.ts`：解析模型输出、分页、元素 ID、diff |
| 渲染/导出 | Playwright（系统 Chrome）+ pptxgenjs | `server/src/render.ts` |
| 前端 | React 19 + Vite + React Router | 预览用 iframe + 注入的选择脚本（`web/src/lib/slideHtml.ts`） |

### 关键设计

- **文档结构**：`{ title, width, height, head, css, readme, pages: [{ id, file, html }] }`。多个样式文件以 `/* ==== file: styles/x.css ==== */` 分隔存于 `css` 中，组装时 `@import` 自动置顶；旧项目自动显示为 `styles/main.css` 与按版式命名的页面文件。每页是一个 `<section class="slide" data-page-id>`，页内每个元素带稳定的 `data-eid`，用于选择、提示词定位与修改历史比对。
- **修改流程**：创建任务 → （单页/元素修改时渲染截图）→ 构造提示词 → 流式调用模型（可调用只读文件工具）→ 解析为草稿 → 自检循环（`server/src/draft.ts`：渲染、布局检查、模型用草稿工具修复）→ 在项目锁内基于**最新**文档应用（单页/元素修改只替换该页）→ 计算 diff → 写入新版本。
- **工具调用**：`llm.ts` 的 `chatWithTools` 实现 OpenAI 风格的函数调用循环（流式合并 `tool_calls`，工具返回的图片以紧随其后的 user 消息转发，最后一轮 `tool_choice: none` 强制作答）；文件工具在 `fileTools.ts`，草稿工具在 `draft.ts`。自检阶段不再重发初稿 HTML（模型用 `read_draft` 按需读取），并只保留原提示中的前 6 张图片，以控制上下文（DeepSeek 在线版上下文 200k）。
- **扩展点**：新增导出格式在 `routes/projects.ts` 的 export 中添加；新增模型协议在 `llm.ts` 中扩展 `chatWithEndpoint`；新增项目类型只需扩展 `projects.type` 与 `prompts.ts`。

## 从 GitHub Actions 预编译包部署（服务器无需 npm）

每次推送到 `main`，GitHub Actions（`.github/workflows/release.yml`）会编译前后端并发布一个 Release：每种 CPU（x64 / arm64）一个安装包，内含编译好的程序、生产依赖 `node_modules` 和 Node.js 运行时，约 75MB。服务器只需下载这一个文件，**不访问 npm、不下载 Node.js**，适合公司代理拦截 npm 的环境：

```bash
curl -fsSLO https://raw.githubusercontent.com/Zhang-JK/http-roadshow-master/main/deploy_from_action.sh
sudo -E bash deploy_from_action.sh                          # 安装；已安装时更新到最新预编译版本
sudo -E bash deploy_from_action.sh --proxy http://proxy:8080 --ca-cert corp-root.crt --port 9090
```

- 先测试能否访问 GitHub 发布清单，再下载安装包并校验 SHA256，然后交给包内的 `deploy.sh` 完成安装（系统用户、systemd、开机自启等与下文相同）。代理、证书参数与 `deploy.sh` 一致（`--proxy`、`--ca-cert 文件|auto`、`--insecure`），其他参数（`--port`、`--base`、`--user` 等）原样传给 `deploy.sh`。
- 之后网页「系统更新」和 `roadshow-studio update` 都从 GitHub Release 获取新的预编译包（配置中 `PREBUILT=1`，不会再走 npm）。
- 服务器连 GitHub 也访问不了时：在能上网的电脑上从 Release 页面下载对应的 `roadshow-studio-…-linux-x64.tar.gz`，复制到服务器后执行 `sudo bash deploy_from_action.sh --file 安装包.tar.gz`。也可以把 Release 中的文件放到内网服务器上，用 `--manifest http://内网地址/latest-linux-x64.json` 安装和更新。
- `--tag r1.1.0-abc1234` 安装指定版本；`--repo 用户/仓库` 使用 fork。也可在本地执行 `bash scripts/package-prebuilt.sh x64 输出目录` 生成同样的安装包（需先编译并 `npm prune --omit=dev`）。

## 部署到 Linux 服务器（推荐）

支持 Ubuntu/Debian、CentOS/RHEL/Rocky、openSUSE 等（x86_64 / arm64）。脚本自动安装 Node.js 22、中文字体、浏览器（用于 PDF/PPT 导出），以独立系统用户 `roadshow` 运行，有 systemd 时注册为 `roadshow-studio` 服务（开机自启、崩溃自动重启），否则使用内置守护进程。

```bash
# 从 git 仓库安装（以后可在线检查/更新该分支的最新提交）
sudo bash deploy.sh install --repo https://github.com/<org>/roadshow-studio.git --branch main

# 或：从发布包清单安装（以后检查 latest.json 中的 version）
sudo bash deploy.sh install --manifest https://your-host/roadshow/latest.json

# 或：直接用当前目录的代码安装（之后用 update --from 手动更新）
sudo bash deploy.sh install
```

安装完成后访问 `http://<服务器IP>:9090`（默认账号 `admin / admin123`，可用 `--admin-password` 指定）。

**一键检查更新 / 更新部署**

- 网页：管理员 →「系统更新」→「检查更新」→「立即更新」。页面实时显示进度与部署日志，服务重启期间自动等待恢复。系统每 6 小时自动检查一次，有新版本时导航栏显示红点。
- 命令行：`sudo bash deploy.sh`（未安装则安装，已安装则检查并更新），或使用已注册的 `roadshow-studio` 命令：

```bash
roadshow-studio check            # 检查更新（--json 输出机器可读结果）
roadshow-studio update           # 更新部署（--yes 跳过确认，--force 强制重建，--from PATH 用本地代码/压缩包）
roadshow-studio rollback         # 回滚到上一个版本，并恢复更新前的数据库备份
roadshow-studio status           # 版本、端口、更新源、运行状态
roadshow-studio logs -f          # 应用日志
roadshow-studio restart | stop | start
sudo roadshow-studio uninstall   # 卸载程序（保留数据；--purge 连同数据删除）
```

**更新流程**：获取新代码 → 在新的 `releases/<时间>` 目录中安装依赖并构建（不影响正在运行的服务）→ 备份 SQLite 数据库 → 切换 `current` 软链接并重启 → 健康检查（确认 `/api/health` 返回新版本号）。构建失败时服务不受影响；新版本无法启动或反复崩溃时自动切回旧版本并恢复数据库。默认保留最近 3 个版本与 7 份数据库备份。

**安装选项**：`--port`（默认 9090）、`--host`（默认 0.0.0.0）、`--base`（默认 `/opt/roadshow-studio`）、`--user`、`--no-systemd`、`--npm-registry https://registry.npmmirror.com`、`--node-mirror https://npmmirror.com/mirrors/node`（国内网络）。非 root 用户也可安装到自己有权限的目录（如 `--base ~/roadshow`），此时跳过系统依赖安装并使用内置守护进程。下载的安装包、解压和 Chromium 下载等临时文件都放在 `<安装目录>/tmp`（不占用 /tmp），应用运行时的转换临时文件也在这里。用 sudo 安装到家目录（如 `--base ~/deploy`）而默认服务用户 `roadshow` 无权进入时，会自动改用执行 sudo 的用户运行服务（或用 `--user` 指定）。

### 公司代理 / HTTPS 证书

安装和更新前会先做**网络连接检测**（不安装任何东西）：代理端口是否可连、Node.js 下载源、npm 仓库，并实际下载最大的依赖包（`better-sqlite3`，约 11MB，含预编译二进制）核对 SHA512，以发现「仓库能访问但安装包被代理拦截或替换」的情况，以及 git 仓库或发布清单、系统软件源、Chrome 下载源、模型接口。任何必需项不通时直接停止，并说明原因（DNS 失败、连不上、超时、代理要求认证、证书不受信任及其签发者等）和建议的参数。也可单独运行：

```bash
sudo -E bash deploy.sh nettest                                   # 用当前环境变量里的 https_proxy
sudo bash deploy.sh nettest --proxy http://proxy.corp:8080
```

公司代理会解密 HTTPS 并用自己的根证书重新签名，因此常见的「无法获取 Node.js 版本列表」实际是证书校验失败。按推荐顺序：

```bash
# 1. 推荐：信任公司根证书（从 IT 获取，PEM 或 DER 均可）
sudo bash deploy.sh install --proxy http://proxy.corp:8080 --ca-cert /path/corp-root-ca.crt

# 2. 让脚本从代理返回的证书链中取根证书（会打印主题与 SHA256 指纹，请与 IT 核对）
sudo bash deploy.sh install --proxy http://proxy.corp:8080 --ca-cert auto

# 3. 拿不到证书时：关闭证书校验（不安全，仅限可信内网）
sudo bash deploy.sh install --proxy http://proxy.corp:8080 --insecure
```

- 不加 `--proxy` 时默认使用 `https_proxy`/`http_proxy` 环境变量（用 `sudo` 运行时也会读取调用者的这两个变量，以及 `no_proxy`）；两者都没有时沿用上次保存的代理（网页一键更新即依赖这一点）；`--proxy none` 表示直连。需要认证的代理写成 `http://用户:密码@proxy:8080`（日志中密码会被隐藏）；`--no-proxy .corp.local,10.0.0.0/8` 指定直连地址（本机总是直连）；部署在内网的模型也可以在「模型接入」中为该接入点关闭「使用系统代理」，不必重新部署。
- 证书会复制到 `shared/certs/`，与系统根证书合并后用于 curl、git、npm、apt/dnf、Node.js 下载与 Chrome 下载。
- 有些代理只返回服务器证书而不带根证书，此时 `--ca-cert auto` 会尝试按证书中的「颁发者地址」下载；仍失败时会提示改用文件或 `--insecure`。
- 这些设置保存在 `shared/deploy.conf`，之后的命令行更新和网页一键更新都会沿用，应用本身调用模型接口与下载 Chromium 也走同一代理与证书（`NODE_USE_ENV_PROXY`；`NODE_EXTRA_CA_CERTS` 指向系统根证书库，即使未指定 --ca-cert 也会信任 IT 已安装到系统中的公司根证书；`--insecure` 时为 `NODE_TLS_REJECT_UNAUTHORIZED=0`）。修改时可执行 `sudo roadshow-studio update --force --proxy ... --ca-cert ...`，或用 `--secure` 恢复证书校验。

**目录结构**（`/opt/roadshow-studio`）：`releases/` 各版本、`current` 当前版本、`shared/data` 数据库与素材、`shared/backups` 数据库备份、`shared/logs` 应用与部署日志、`shared/deploy.conf` 部署配置（可修改端口、更新源等后执行 `roadshow-studio restart`）、`shared/extra.env` 额外环境变量（如 `CHROME_PATH`）。

**发布新版本（发布包方式）**：在仓库中执行 `bash scripts/package-release.sh [输出目录] [下载地址前缀]`，生成 `roadshow-studio-<版本>.tar.gz` 与 `latest.json`（含版本、提交、SHA256），上传到任意静态文件服务即可；服务器端会校验 SHA256。git 方式只需推送到所跟踪的分支。版本号 = 根目录 `package.json` 的 `version` + 提交短哈希。

### PPT / PDF / HTML 逐页转图片

上传的演示文稿由 `server/scripts/slides-to-images.sh` 转换（LibreOffice 转 PDF → poppler `pdftoppm` 按页导出 JPEG，宽 1280px，每个文件最多 30 页），也可以单独使用：

```bash

# 生成 输出目录/document.pdf、slide-001.jpg、slide-002.jpg……以及逐页文字 text.txt（以换页符分隔）
```

依赖 `libreoffice-impress`（PDF 输入无需）与 `poppler-utils`，`deploy.sh` 会自动安装；本地开发请自行安装（如 `sudo apt-get install --no-install-recommends libreoffice-impress poppler-utils`）。每次请求最多附带 24 张页面图（多个文件平均分配）、8 张可嵌入图片和 8 张参考图；修改时为 12 / 4 / 6 张。

**模型调用超时**在「模型接入 → 生成设置」中调整：模型连续「无响应超时」（默认 600 秒，含长输入的预填充阶段）没有返回任何数据才会中止，持续输出时不会中止；「单次调用上限」（默认 120 分钟）是一次调用的总时长上限。慢速的本地模型可按「最大输出 tokens ÷ 每秒 tokens 数」估算一次调用的耗时（65536 tokens 在 20 tokens/秒 下约 55 分钟，但分阶段生成时单次调用通常只输出几千到两万 tokens）。「最大输出 tokens」默认 65536（旧版保存的 32000 会自动升级），「上下文窗口 tokens」默认 200000，请按模型实际窗口填写。

## MCP 接入

服务在 `POST /mcp` 提供 MCP（Streamable HTTP，无状态，JSON 响应；协议版本 2024-11-05 至 2025-11-25，使用更新协议的客户端会自动回退）。所有请求以 `mcp` 服务账户的身份执行，需要请求头 `Authorization: Bearer <令牌>`。

1. 管理员打开「用户管理」，在 `mcp` 一行勾选「允许 MCP 请求」（关闭后所有 MCP 请求返回 403，令牌保留）。
2. 在「MCP 接入」卡片点击「生成令牌」。令牌只显示一次，服务端只保存其 SHA-256；重新生成或撤销后旧令牌立即失效。卡片中有可直接复制的客户端配置。
3. 在客户端中配置：

```json
{
  "mcpServers": {
    "roadshow": {
      "url": "http://服务器:9090/mcp",
      "headers": { "Authorization": "Bearer <令牌>" }
    }
  }
}
```

Claude Code：`claude mcp add --transport http roadshow http://服务器:9090/mcp --header "Authorization: Bearer <令牌>"`。

工具：

| 工具 | 作用 |
| --- | --- |
| `list_roadshow_templates` | 列出已生成完成的模板：id、名称、尺寸、风格/用途/受众/配色、版式列表与模板 README 摘要；`includePreviews: true` 时附带每个模板的封面图 |
| `create_roadshow_slides` | 与网页「新建路演材料」相同的输入：`templateId`、`name`、`content`（必填），`purpose`、`audience`、`pageCount`（1–40）、`aspect`（`template` 跟随模板 / `16:9` / `4:3` / `a4-landscape` / `a4-portrait` / `9:16` / `1:1` / `custom` + `width`、`height`）、`notes`，以及最多 12 个 `files`（`filename` + base64 的 `data`，文本文件也可以用 `text`；图片 `role` 为 `embed` 可放进页面、`reference` 仅参考）。支持的格式与网页相同：png/jpg/gif/webp、ppt/pptx/pps/ppsx/odp/key/pdf/html、txt/md/csv/json/xml/yaml/doc/docx。立即返回 `projectId`，生成在后台进行 |
| `get_roadshow_slides_status` | 查询进度（最多等待 `waitSeconds` 秒，默认 20）。完成后返回页面列表、编辑器链接与下载链接（html / pdf / pdf-image / pptx / zip），`includePreviews: true` 时附带前 12 页的截图；失败时返回原因 |

- 输入校验与网页完全一致（同一段代码）；参数错误以工具错误（`isError`）返回，调用方可以据此修正。
- MCP 发起的生成不会暂停向用户提问（没有人能回答），其他设置（自检、交付检查、分步生成）照常。
- 生成的材料出现在「路演材料」中，创建人显示为「MCP」，所有用户都可以继续修改。
- 下载链接需要带同一个 `Authorization` 头，例如 `curl -H "Authorization: Bearer $ROADSHOW_MCP_TOKEN" -o deck.pdf "<pdf 链接>"`；令牌只能下载 MCP 创建的材料，不能访问其他接口。
